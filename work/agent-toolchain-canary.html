02 / Developer tooling + diagnostics

Find the failure before it costs the day.

A standalone Node.js diagnostic toolkit for checking the local developer environment, classifying repeated failures, and producing redacted, reviewable reports.

The problem

Developer workflows can depend on a combination of runtimes, command-line tools, authentication mechanisms, network endpoints, and schedulers. Problems may recur only on particular machines or when processes run unattended.

What the toolkit does

  • Probes Node/npm, Git, CLI availability, read-only GitHub access, HTTPS endpoints, and a local HTML fixture.
  • Stores ignored, redacted local reports and classifies first-seen, recurring, recovering, and retirement-candidate failures across runs.
  • Provides an inspectable, opt-in scheduling process for Windows Task Scheduler, macOS LaunchAgent, and Linux user schedulers.
  • Uses a lock to prevent overlapping runs and avoids storing or printing secret values.

Engineering decisions

The project favors harmless, read-only probes over automated remediation. Its schedule installation and removal require explicit confirmation. Human approval is required before changing durable compatibility guidance.

Verification and limits

Public source, automated test commands, operational guidance, and authentication documentation are available in the repository. Runtime checks cannot stand in for testing connected agent plugins or interactive browser tooling; those remain manual or agent-assisted verification paths. This is not presented as proof of an always-running production monitoring service.
